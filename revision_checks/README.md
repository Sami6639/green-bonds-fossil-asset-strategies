## Reproduction

From the repository root, install the pinned dependencies with `python -m pip install -r requirements.txt`, then run `python run_all.py`. The unified command invokes, in order:

1. `python run_reproduce.py`: verifies input and nested-history manifests, rebuilds the panel, descriptive tables and figures, and runs existing validation.
2. `python strategy_comparison/build_theory_evidence.py`: rebuilds seven-history and principal-group event comparisons.
3. `python decision_rationales/build_audit.py`: rebuilds archived-event field checks.
4. `python decision_rationales/build_evidence.py`: rebuilds source-linked decision-rationale evidence.
5. `python revision_checks/apply_interpretation_corrections.py`: applies the previously documented unsupported-rounding correction to active Constellation displays while preserving raw provenance and numerical values.
6. `python revision_checks/build_revision_checks.py`: rebuilds selection, illustrative timing, economic-magnitude and invariant checks.
7. `python revision_checks/stage_weight_decomposition/build_stage_weight_decomposition.py`: calculates the exact two-date SSE/WEC stage and weight components using disclosed reporting entries, cutoff-specific denominators and achieved-operation codes.

`reproduction_log.json` retains the r4 commands, exit codes, environment and pre-existing CSV comparisons. `final_code_validation.json` separately records unchanged r3 CSV results and frozen-file hashes, exact decomposition checks and a repeated-run determinism test. Runtime timestamps and PDF metadata need not be byte-identical. Reproduction uses the included source-derived records and does not retrieve or independently interpret original issuer reports. The test is not described as network-isolated.

The r4 [decomposition guide](stage_weight_decomposition/README.txt) documents inputs, equations and source-review limits. Its `outputs/stage_weight_decomposition.csv` reports case-level changes and `outputs/project_contributions.csv` reports project contributions. Exact fractions reconcile both components to the observed share change with zero residual. Missing stages, missing amounts and unmatched membership stop the analysis rather than being imputed. The Paris solar/battery entry remains unsplit.

`seven_history_linkage_matrix.csv` separates the available financial, project, monetary-weight, achieved-stage, ownership and timing evidence. `source_audit/evidence_link_definitions.json` defines relational labels, which are neither quality scores nor a ranking. `source_audit/critical_source_review.csv` and `source_audit/source_inspection_scope.csv` record bounded reinspection and the actual text/page-image coverage. These are AI-assisted checks, not independent human coding, and no inter-coder agreement statistic is claimed. Original issuer reports and page images are not redistributed.

The bounded precursor comparison is recorded in `literature/precursor_contribution_matrix.csv`. Alova's publisher-provided first page was inspected, but unobserved Methods fields remain unverified. Page locators for the accessible Tuhkanen and Christy copies retain their early-version pagination. `literature/bibliography_live_refresh.csv` and the accompanying JSON records verify the four requested DOI metadata entries without unnecessary bibliography changes. These updates do not claim a fresh full-text audit of all bibliography sources.

`manuscript_identity.json` records the current title, six keywords, count definitions and exact main-file identity. `final_citation_check.json` is regenerated from the actual current main and supplementary Word files, with normal/blinded citation comparisons and final bibliography matching. The unchanged citation-checking script retains its r4 method/version label; the r5 audit records that provenance separately from this synchronization identifier. To repeat the internal citation check on your copies, run:

```
python revision_checks/check_final_citations.py --main /path/to/main.docx --supplementary /path/to/supplementary.docx --blind-main /path/to/blinded-main.docx --blind-supplementary /path/to/blinded-supplementary.docx
```

Those example paths refer to documents supplied separately, not repository files. The check does not modify the documents. It verifies author-year/bibliography matching, duplicate keys and DOIs, and visible DOI hyperlink targets; live metadata and source interpretation are distinct checks. A complete document-level audit is not part of run_all.py because the associated Word files are not redistributed here.

## Revision outputs and interpretation

- `selection_flow.csv` and `selection_reconciliation.csv`: overlapping screening layers and 64 detailed candidate IDs. The WBA 2023 frame has 68 published labels; source screening evidence has 154 records (68 frame, 37 remaining-screen, 49 additional-coverage records). These are overlapping record sets, not a summed count of independent screened companies. The 64-ID detailed register has 49 IDs with numeric records and 15 without. Of the former, 37 are admitted and 12 are not. The 27 nonadmitted IDs include exclusions and unresolved records; lack of extraction is not evidence of ineligibility. Admission is 37 contextual groups = 33 principal + 4 thermal proxies, with 32 principal pairs because ESB's same-window renewable total is unresolved. The 2023 frame is retrospectively applied to earlier observations; public disclosure and accessible comparable endpoints condition coverage. No global population denominator is asserted.
- `timing_comparison.csv`: eight illustrative adjacent fossil-aggregate windows within the main windows of five groups (Ameren, AES, WEC, NextEra and Shikoku), selected for an explicit comparable aggregate and interpretable retained finance evidence. This is a bounded illustration, not all 29 groups in the 142-row finance-aligned category output and not a new estimate of the 32-group paired result. The original adjacent-category output has overlapping category/window rows, including conditional gates. Long-window decline is preserved in AES but becomes unchanged for Ameren, changes sign in Shikoku, and contains offsetting short-period directions in WEC and NextEra. Finance date bounds and classes, source date bounds and record IDs are retained. Year-only rows follow year-end headings established in the reviewed source, while original lower/upper date bounds remain visible. Financing observed within or at the end of a window does not show it was active throughout. Capacity changes can precede the retained finance observation; no post-financing causal effect is estimated.
- `timing_capacity_provenance.csv` and `timing_finance_provenance.csv`: exact retained source records behind the selected timing rows. An earliest retained financing observation is not necessarily the first issue.
- `economic_magnitude_examples.csv` and `economic_magnitude_provenance.csv`: Ameren, JSW and WEC endpoints, changes and source rows, illustrating magnitude without representativeness claims. A consistent reporting basis does not establish a constant asset perimeter. Acquisitions, sales, reactivation and reclassification can contribute. No cross-company MW total is computed. Percentage change is not reported for a zero starting value.
- `invariant_checks.json`: 37/33/32, 18/8, 13/8 at both bands, SSE 6.84%/69.48%, WEC 33.46%, and Enel EUR156.86m (2019 bond) versus EUR229.60m (all issues) are computationally reconciled. Dominion remains outside the main panel. Bands are descriptive thresholds, not significance tests. Event-family tables retain all asset types and are not fossil-only retirement censuses.

Blank/NaN values represent unknown or unavailable quantities and are never recoded to zero. Stage shares use disclosed allocation amounts, not project counts; SSE fixed weights and WEC cutoff-specific weights must not be interpreted as interchangeable. Source-interpretation corrections are documented separately from computational reproducibility. New revision-table provenance resolves original extraction paths to the repository-relative frozen inputs through the snapshot manifest. Historical frozen source-path fields remain unchanged and are not required local paths for rerunning this package.

## Source interpretation correction

`source_interpretation_corrections.csv` is a dated, field-specific interpretive overlay. For Constellation's 2024 allocation, displayed categories USD170m + USD237m + USD135m sum to USD542m, whereas the reported total is USD541m. The signed residual (reported total minus the displayed category sum) is -USD1m. Original wording that described this as source-explained rounding is superseded: rounding is plausible but is not explicitly explained in the reviewed source and remains unreconciled. The overlay preserves the numerical values and frozen source records. The unified entry point also applies the correction to seven active derived display CSVs and writes corrected_output_manifest.json; those corrected files are included in this revision. Quoted raw-source JSON and historical handcoding retain their original wording as provenance and must be read with this dated correction. Running the four legacy commands alone reconstructs the old wording; run_all.py applies the scientific correction after those stages. corrected_numeric_equivalence.json verifies that no numerical data changed. The main manuscript and Supplementary Information incorporate the corrected interpretation.
